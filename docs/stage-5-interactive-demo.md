# 第五阶段：可交互演示工作台

## 阶段目标

将前四阶段的银行数据、确定性权限控制和 Agent 编排能力整合为一套可在答辩现场直接操作的 Web Demo。页面不是静态原型：所有业务结果、任务状态、风险等级和审计事件均来自 FastAPI 服务。

## 已完成能力

- 自然语言对话：创建服务端会话并在后续请求中复用 `conversation_id`。
- 五个预置演示指令：资产查询、账单分析、订阅查询、小额转账和大额转账。
- 收款人消歧：当“小王”匹配多位联系人时，展示银行、脱敏账号和别名供用户选择。
- 黄色权限：小额转账展示金额、收款人和付款账户，只有明确确认后才继续。
- 红色权限：大额转账暂停在强验证节点，输入六位短信验证码后才执行；演示码为 `246810`。
- 人工接管：强验证阶段可主动请求人工协助；未知或疑似注入意图由后端自动转入人工复核。
- 实时 DAG：按计划节点显示已完成、当前暂停和待执行状态。
- 策略驾驶舱：显示业务意图、运行状态、模型来源、置信度和计划哈希。
- 审计驾驶舱：展示最新安全事件及哈希链完整性，并同步账户锁定状态。
- 响应式布局：桌面端为对话与安全驾驶舱双栏，移动端自动转为纵向布局。

## 推荐的 5 分钟演示脚本

### 1. 绿色：查询与分析（约 50 秒）

点击“查询总资产”，说明查询类操作无需二次确认，右侧权限等级为绿色，DAG 自动完成。随后点击“分析 8 月账单”，展示账单总支出、交易笔数，以及任务与审计记录的同步更新。

### 2. 黄色：小额转账（约 80 秒）

点击“小额转账”。系统先识别到两位“小王”，要求用户选择收款人；选择任意联系人后，系统创建草稿并由服务器策略引擎判定风险。页面显示黄色确认卡，核对详情后点击“确认转账”，展示银行回单号。强调大模型不能绕过此确认节点。

### 3. 红色：大额转账（约 80 秒）

点击右上角“新会话”，再点击“大额转账”。系统判定金额超过日累计阈值，暂停在红色强验证节点。输入演示验证码 `246810`，点击“验证并执行”，展示回单号。可指出连续三次错误验证码会触发十五分钟锁定。

### 4. 安全与可解释性（约 50 秒）

指向右侧任务 DAG、计划哈希和审计事件，说明操作权限由确定性规则引擎裁决，Agent 只负责理解与规划；每次关键操作都写入前后相连的哈希审计链。可补充输入提示注入内容时，系统会拒绝自动执行并转交人工。

## 本地运行

推荐使用仓库根目录的 Docker Compose：

```powershell
docker compose up --build
```

打开 <http://localhost:3000>。后端 API 文档位于 <http://localhost:8000/docs>。

若分别启动前后端，确保前端环境变量与后端地址一致：

```powershell
$env:NEXT_PUBLIC_API_BASE_URL="http://localhost:8000"
pnpm dev:web
```

- `pnpm --dir apps/web lint`：通过。

- 独立 SQLite 演示库迁移与种子数据：通过。

- 黄色转账消歧、确认、执行：`completed`，生成回单号。
- 红色转账强验证、执行：`completed`，生成回单号。

## 安全边界

前端只展示并提交用户意图，不自行计算权限等级，也不把按钮状态视为授权。最终风险判定、验证码校验、幂等执行、锁定和审计全部在服务端完成。页面中展示的风险等级来自不可由用户直接修改的服务端运行计划；即使绕过页面直接调用接口，也必须经过相同安全控制。
