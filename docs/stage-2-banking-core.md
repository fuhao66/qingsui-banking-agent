# 第二阶段：模拟银行核心

## 阶段成果

第二阶段把第一阶段的静态演示扩展为可查询、可验证的模拟银行数据层。所有账户与交易均为虚构的沙箱数据，不连接真实银行或支付网络。

## 数据模型

| 表 | 作用 | 关键约束 |
| --- | --- | --- |
| users | 演示客户身份 | 客户号唯一 |
| accounts | 活期与储蓄账户 | 余额非负、状态受限 |
| payees | 用户常用收款人 | 仅保存掩码与沙箱令牌 |
| transactions | 12 个月交易账本 | 金额为正、外部流水号唯一 |
| subscriptions | 周期性代扣识别结果 | 金额为正、状态受限 |
| transfer_drafts | 待审批转账草案 | 不直接移动资金 |

首个 Alembic 迁移为 20260903_0001_initial_banking_core.py，支持升级和回退。

## 演示数据

- 1 名虚构客户：刘女士；
- 2 个账户：工资卡与储蓄账户；
- 6 名收款人，其中“小王”对应两人，用于演示消歧；
- 5 个活跃订阅；
- 连续 12 个月的收入、住房、餐饮、交通、购物和订阅交易；
- 1 笔带 UNUSUAL_TIME_AND_REGION 标记的异常交易；
- 固定 ID 和固定业务数据，便于视频录制与自动测试。

种子命令可重复执行，检测到演示用户后不会重复插入数据：

    python -m app.db.seed

## API

| 方法与路径 | 能力 |
| --- | --- |
| GET /api/v1/users/me | 获取演示客户资料 |
| GET /api/v1/accounts | 获取账户及资产合计 |
| GET /api/v1/accounts/{id} | 获取单一账户 |
| GET /api/v1/transactions | 按账户、类别和时间筛选交易 |
| GET /api/v1/bill-summary?month=2026-08 | 从账本确定性计算月度汇总 |
| GET /api/v1/payees/search?q=小王 | 查询联系人并返回是否需要消歧 |
| GET /api/v1/subscriptions | 获取订阅与月度等值费用 |
| POST /api/v1/transfer-drafts | 创建待策略审批的转账草案 |
| GET /api/v1/transfer-drafts/{id} | 查询转账草案 |

## 安全边界

本阶段刻意不提供资金提交接口。POST /transfer-drafts 只进行所有权、账户状态、币种、余额和金额检查，并将状态保存为 pending_policy。第三阶段加入权限判定、参数签名、用户确认、强认证与幂等执行后，才会开放受控提交链路。

模型未来只能访问查询和草案工具，不能直接获得核心账务写权限。

## 验证

- 数据模型可在测试数据库完整建表；
- Alembic 迁移升级和回退通过；
- 种子数据可重复运行；
- 账户、流水、账单、联系人、订阅和草案接口均有自动测试；
- 账单统计来自交易账本，不由模型计算；
- 余额不足的草案请求返回稳定错误码。
