# 第七阶段：自动化评测与 Demo 一键重置

## 阶段目标

把“能演示”升级为“可重复验证、可快速复位”。评测器只调用意图理解与白名单规划，不执行业务工具，不会创建转账、取消订阅或修改卡片；重置能力则被限制在 development 演示环境。

## 自动化评测系统

评测数据位于 `services/api/evals/cases.json`，当前包含 40 条用例：

- 账户、账单、订阅、卡片、理财、转账和范围外请求；
- 金额、月份、期限、风险偏好、银行卡尾号和收款人槽位；
- 10 条中英文提示注入、权限绕过、工具注入和秘密提取攻击；
- 绿、黄、红最高风险等级与工具注册表校验。

运行方式：

```powershell
.\scripts\run-evals.ps1 -Provider deterministic
.\scripts\run-evals.ps1 -Provider qwen
.\scripts\run-evals.ps1 -Provider qwen -Limit 5
```

脚本从根目录 `.env` 向评测子进程注入对应服务端配置，不输出密钥，并在结束后恢复原进程环境变量。报告写入被 Git 忽略的 `data/eval-report-<provider>.json`，包含逐条预测、期望槽位、风险、模型来源、延迟、错误类型和白名单违规。

## 混合槽位规范化

评测发现在线模型能正确判断意图，但可能将“两万”“半年”“随时能取”等显式值返回为不同格式。系统因此采用混合方法：

1. LLM 负责语义意图和隐含表达理解；
2. 确定性解析器从原始用户文本重新提取显式金额、月份、期限、卡号和风险词；
3. 规范化结果覆盖同一显式槽位；
4. Pydantic 再次校验，最后才进入白名单 DAG。

这可以减少模型输出格式波动，同时不扩大模型权限。

## 一键重置 Demo

Web 顶栏新增“重置数据”按钮。用户确认后调用：

```http
POST /api/v1/demo/reset
Content-Type: application/json

{"confirmation":"RESET_DEMO_DATA"}
```

重置过程会串行删除沙箱业务数据，重新写入确定性种子数据，再创建 `demo.data.reset` 审计事件。结果包括：

- 工资卡余额恢复为 `28640.52`；
- 银行卡恢复正常；
- 五项订阅恢复有效；
- 历史会话、运行、认证挑战和转账执行记录清空；
- 审计链从重置事件建立新的完整起点。

当 `APP_ENV` 不是 `development` 时，接口固定返回 `403 DEMO_RESET_DISABLED`。

## 验收结果

- 重置接口恢复种子余额并清空历史运行；
- 重置后的审计哈希链完整；
